# Интеграция dh-carpet с 1С

Это отдельная интеграция; старая обработка `shop.dinastyhan.ru` не изменяется. Транспорт: 1С формирует JSON и отправляет HTTPS POST в `/api/internal/1c/bulk` с заголовком `X-Internal-API-Key`. Ключ хранится вне исходников 1С и Git.

Подтверждены `Справочник.Номенклатура`, его перечисленные в проектной документации поля, `РегистрНакопления.Запасы.Остатки`, `РегистрСведений.ЦеныНоменклатуры` и вид цен с наименованием `Розничная цена`. Файл `Transport.bsl` не зависит от метаданных прикладных документов. `CatalogExport.bsl` содержит запрос только к подтверждённым полям номенклатуры.

Metadata discovery прикладных документов завершён. `SalesAdapter.bsl` читает только `Документ.РасходнаяНакладная.Запасы` с видом операции `ПродажаПокупателю`; `CustomerReturnsAdapter.bsl` — только `Документ.ПриходнаяНакладная.Запасы` с видом операции `ВозвратОтПокупателя`. Оба адаптера формируют полный snapshot одного документа, используют `Ссылка.УникальныйИдентификатор()` и `ИдентификаторСтроки`, не записывают данные в 1С и не используют `НомерСтроки`.

Для проведённого целевого документа пакет содержит все строки и `posted=true`. При распроведении либо смене вида операции отправляется пустой `document_snapshots`-snapshot с `posted=false`, чтобы backend скрыл ранее принятые строки. Смещение часового пояса (для production `+03:00`) передаётся адаптеру явным параметром. Пакет отправляется существующей функцией `ОтправитьПакетDhCarpet`.

BSL-файлы являются исходниками серверных общих модулей расширения/агента 1С. После записи расходной или приходной накладной агент должен сформировать пакет соответствующей экспортной функцией и отправить его. Адрес backend и API key по-прежнему берутся только из защищённых настроек. Диагностические `MetadataDiscovery*.bsl` можно оставить отдельно; для штатной синхронизации они больше не требуются.

`DocumentEventHandlers.bsl` содержит безопасные обработчики подписок `ПриЗаписи`, `ProtectedSettings.bsl` — серверный доступ к безопасному хранилищу БСП. В `ПриЗаписи` адаптеры строят snapshot непосредственно из переданного объекта документа, не перечитывая ещё не зафиксированное состояние по ссылке. Точная схема модулей, их свойства, подписки и ручная проверка описаны в [`docs/1c-sales-returns-installation.md`](../../docs/1c-sales-returns-installation.md).

Расширение должно самостоятельно проверять отдельное право просмотра истории перед запросом history/graph API. Подтверждение и отклонение цен Лалиты из 1С не реализуются: это административная операция dh-carpet.
