# Первоначальная выгрузка каталога из 1С

Каталог передаётся в существующий endpoint `POST /api/internal/1c/bulk`: `mode=initial`, массив `rugs`, пустые `events` и `document_snapshots`. Backend принимает не более 1000 ковров в одном запросе; `CatalogAdapter.bsl` использует партии по 200 позиций. Повторный запуск безопасен: backend выполняет upsert по barcode и возвращает per-item результат.

Продажа или возврат не создаёт ковёр автоматически. До повторной проверки накладной №1648 нужно один раз выполнить эту выгрузку.

## Отбор и запросы 1С

Главный набор строится от `Справочник.Номенклатура`. Рекурсивно обходятся ровно три подтверждённых корня:

- `Ковры` → `category=rug`;
- `Ковролины` → `category=carpet`, включая находящиеся внутри дорожки;
- `Шкуры` → `category=hide`.

Группы и элементы с `ПометкаУдаления=Истина` исключаются. Несуществующее имя `Ковролины (в т.ч. дорожки)` не используется. Каждое имя корня должно однозначно находить одну непомеченную группу; иначе выгрузка останавливается с диагностикой.

Остатки читаются пакетно из `РегистрНакопления.ЗапасыНаСкладах.Остатки` по ресурсу `КоличествоОстаток`. Цены читаются пакетно из `РегистрСведений.ЦеныНоменклатуры.СрезПоследних` с условием `ВидЦен.Наименование = "Розничная цена"`. `ПолучитьОбъект()` для каждой позиции и прямой SQL не используются.

## Mapping 1С → backend

| 1С | Поле `rugs[]` | Правило |
|---|---|---|
| `Штрихкод` | `barcode` | Обязательный business ID, максимум 64 символа |
| `Наименование` | `name` | Обязательное поле |
| `Артикул` | `article` | Передаётся при длине не более 100 символов |
| корневая группа | `category` | `rug`, `carpet` или `hide` |
| — | `status` | Всегда `unknown`; остаток не определяет бизнес-статус |
| `Ширина` | `width_cm` | Передаётся только положительное значение |
| `Длина` | `length_cm` | Передаётся только положительное значение |
| `Вес` | `weight_kg` | Передаётся неотрицательное значение |
| `Описание`, затем `Комментарий` | `description` | Комментарий используется как fallback |
| сумма `КоличествоОстаток` | `stock_qty` | Нулевой остаток передаётся как `0` |
| `СтруктурнаяЕдиница`, `Ячейка`, количество | `locations[]` | Все положительные остатки агрегируются только по склад/ячейка |
| однозначный `Цена` | `retail_price` | Только `Розничная цена` |
| `ЕдиницаИзмерения` цены | `retail_price_unit` | При длине до 50 символов |
| `ВалютаЦены` | `currency` | RUB/рубль → `RUB`, также допускаются точные `USD` и `EUR` |
| UUID ссылки номенклатуры | `raw_payload.nomenclature_uuid` | `Ссылка.УникальныйИдентификатор()` |

`current_location` не заполняется: у проекта нет правила выбора одной основной локации. Все исходные строки остатков, включая организацию, характеристику, UUID склада и UUID ячейки, сохраняются в `raw_payload.location_rows`. В `locations[]` строки разных организаций/характеристик одного склада и ячейки суммируются. Пустая ячейка допустима.

Все строки розничной цены с характеристиками, единицей и валютой сохраняются в `raw_payload.retail_price_rows`. Если записи разных характеристик имеют одинаковые цену, единицу и валюту, общее значение передаётся в прямые поля. Если значения различаются, произвольная запись не выбирается: прямое поле цены не заполняется, а отчёт содержит `multiple_retail_prices`.

Позиции без barcode не скрываются: они попадают в `local_errors` с кодом `missing_barcode` и не включаются в HTTP-пакет, чтобы Pydantic не отклонил весь запрос. При дублировании barcode не отправляется ни один участник дубля; для каждого создаётся `duplicate_barcode`. Аналогично явно диагностируются отсутствующее имя и превышение лимита barcode. Предупреждения и исходные значения сохраняются в итоговом JSON-отчёте.

## Объекты расширения

Все объекты создаются в существующем расширении `ДХКоверИнтеграция`; конфигурация поставщика не изменяется.

### Роль

1. В дереве расширения откройте `Общие → Роли` и создайте роль `ДХКоверАдминистраторИнтеграции` с синонимом `Администратор интеграции dh-carpet`.
2. После обновления базы назначьте эту роль только пользователю, который будет выполнять первоначальную выгрузку.

`CatalogAdapter.bsl` дополнительно проверяет роль на сервере через `РольДоступна`. Одной видимости команды в интерфейсе недостаточно.

### Общий модуль

1. Откройте `Общие → Общие модули` и создайте `ДХКоверКаталогСервер`.
2. Установите: `Глобальный — Нет`, оба клиентских флага — `Нет`, `Сервер — Да`, `Вызов сервера — Нет`, `Внешнее соединение — Да`, `Привилегированный — Нет`, `Повторное использование — Не использовать`.
3. Целиком вставьте `integrations/1c/CatalogAdapter.bsl` в модуль.

### Общая форма

1. В `Общие → Общие формы` создайте `ДХКоверПервоначальнаяВыгрузкаКаталога`, синоним `Первоначальная выгрузка каталога dh-carpet`.
2. Создайте реквизит формы `РезультатВыгрузки`, тип `Строка`, длина `0` (неограниченная).
3. Добавьте поле реквизита на форму. Установите `Многострочный режим — Да`, `Только просмотр — Да`, заголовок `Результат выгрузки`.
4. В командах формы создайте `ВыполнитьВыгрузку` с заголовком `Выполнить первоначальную выгрузку` и поместите кнопку на командную панель.
5. Целиком вставьте `integrations/1c/CatalogImportFormModule.bsl` в модуль формы.

### Команда открытия

1. В `Общие → Общие команды` создайте `ДХКоверОткрытьПервоначальнуюВыгрузкуКаталога`, синоним `Первоначальная выгрузка каталога dh-carpet`.
2. Оставьте `Тип параметра команды` пустым, установите `Группа — Панель навигации.Обычное`, `Изменяет данные — Да`.
3. Целиком вставьте `integrations/1c/CatalogImportOpenCommand.bsl` в модуль команды.
4. В роли `ДХКоверАдминистраторИнтеграции` разрешите просмотр созданных общей формы и общей команды.
5. Заимствуйте в расширение существующую подсистему с синонимом `Администрирование`, включите в её состав новую общую команду и включите её видимость в командном интерфейсе только для административной роли.

Если техническое имя подсистемы отличается, выбирайте её по реальному синониму и назначению в конфигурации — имя не следует угадывать.

## Ручной запуск

1. Выполните `Конфигурация → Проверка конфигурации`.
2. Сохраните расширение и выполните `Конфигурация → Обновить конфигурацию базы данных`.
3. Перезапустите сеанс пользователя с ролью `ДХКоверАдминистраторИнтеграции`.
4. Откройте `Администрирование → Первоначальная выгрузка каталога dh-carpet`.
5. Нажмите `Выполнить первоначальную выгрузку` и подтвердите действие.
6. Дождитесь завершения и скопируйте целиком JSON из поля `Результат выгрузки`.

В отчёте проверяются `status`, `catalog_items_found`, `ready_items`, `sent_items`, `backend_succeeded`, `backend_failed`, `local_errors`, `warnings` и `runs`. При сетевой ошибке отправка следующих партий прекращается; повторный ручной запуск продолжает работу через идемпотентный upsert.

Выгрузка не запускается автоматически, не связана с записью накладных и не является регламентным заданием.
